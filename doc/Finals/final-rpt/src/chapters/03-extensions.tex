\subsection{乘除法与 B 扩展多周期控制}

乘法器按操作类型选择普通低位、全宽高位或窄操作数快速通路；除法器采用恢复除法，每拍执行移位、
比较与减法，最后单独完成符号修正。当前 RTL 的迭代 B 单元只保留 \code{clz/ctz}，逐位执行 32 轮；
移位加法、符号扩展、最小/最大值、逻辑否定组合、\code{rol} 左旋、字节反序和单比特操作保留在短组合
通路。当前支持范围仅以表~\ref{tab:implemented-extensions} 为准；旧迭代单元中的其余操作不再支持。
\code{pack} 由当前单周期快速整数通路实现。

多周期请求被接受后，流水线相关信息仍保留目的寄存器号，但将 \code{dataValid} 保持为 0；因此依赖
该结果的年轻指令会在 IDU 停顿，而无关指令不会把未完成的数据误认为可前递结果。执行单元寄存最终
结果后置位 \code{dataValid}，待后级 \code{ready} 有效时完成握手并释放占用。该协议统一覆盖乘法、
除法、迭代 B 操作以及后述阻塞式加速单元。

\subsection{B 扩展的动态热点与性能边界}

\subsubsection{\texttt{xcrcu8}：单字节 CRC 状态变换}

令输入数据字节 $d=\mathrm{rs1}[7:0]$，当前 16 位 CRC 状态 $c=\mathrm{rs2}[15:0]$，并令
$v=d\Vert c\in\mathbb{F}_2^{24}$。硬件用固定异或网络实现线性映射
\begin{equation}
  \mathrm{rd}[15:0]=M_{\mathrm{CRC}}v,\qquad \mathrm{rd}[31:16]=0,
\end{equation}
其中 $M_{\mathrm{CRC}}\in\mathbb{F}_2^{16\times24}$ 为 CRC 更新多项式展开后得到的常量矩阵，矩阵
乘加均在 $\mathbb{F}_2$ 上进行。等价的逐位参考算法如下；其中 $\oplus$ 表示按位异或。
\begin{algorithm}[H]
\caption{单字节 CRC 状态更新}\label{alg:crcu8}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\State $next\gets crc[15:0]$
\State $value\gets data[7:0]$
\For{$i\gets 0$ \textbf{to} $7$}
  \State $x\gets (value\oplus next)[0]$
  \State $value\gets value\gg1$
  \If{$x=1$}
    \State $next\gets next\oplus\mathtt{0x4002}$
  \EndIf
  \State $next\gets(next\gg1)\mathbin{|}(x\ll15)$
\EndFor
\State \Return $next[15:0]$
\end{algorithmic}
\end{algorithm}
\CodeCompareBegin{C 语句片段}{生成的 RV32 汇编}
\noindent\begin{minipage}[t]{0.48\linewidth}
\begin{lstlisting}[style=cstatement]
for (i = 0; i < 8; ++i) {
  x16 = (data & 1) ^ (crc & 1);
  data >>= 1;
  if (x16) crc ^= 0x4002;
  crc = (crc >> 1) | (x16 << 15);
}
\end{lstlisting}
\end{minipage}\hfill
\begin{minipage}[t]{0.48\linewidth}
\begin{lstlisting}[style=rv32statement]
(*@\CustomInsn{.insn r 0x0b, 0, 0, a0, a0, a1}{xcrcu8}@*)
\end{lstlisting}
\end{minipage}\CodeCompareEnd
该指令不访问存储器、不保留跨指令状态，并在单周期结果通路写回。相同 ISA 配置和迭代数的板级对比
中，它将运行时间由 10.07521570~s 降至 9.56506582~s，减少 0.51014988~s（5.0634\%）。

\subsubsection{\texttt{xmacacc}：矩阵乘累加序列}

\code{xmacacc} 在窄 16-bit 乘法器旁设置 32-bit 累加器 $A$，用 first、add、last 三个阶段表达一个
点积。每个阶段都有 signed 和 bit 两种形式，共对应六条编码。令
\begin{align}
  T_s(a,b)&=\mathrm{sext}_{32}(a[15:0])\times\mathrm{sext}_{32}(b[15:0]),\\
  q&=\mathrm{zext}(a[15:0])\times\mathrm{zext}(b[15:0]),\\
  T_b(a,b)&=\mathrm{zext}(q[5:2])\times\mathrm{zext}(q[11:5]).
\end{align}
其中 signed 形式由无符号窄乘积减去两个符号修正项得到二补码乘积，bit 形式则在同一窄乘积上执行
与 \code{xmbm} 相同的字段提取。first 以本项覆盖 $A$，add 将本项累加到 $A$ 且不写 GPR，last
累加末项并把最终 $A$ 写入 \code{rd}。统一算法如下。

对长度为 $n\geq2$ 的点积，编译器把首项映射为 first，中间各项映射为 add，末项映射为 last：
\begin{equation}
  A_0=T(a_0,b_0),\qquad
  A_k=(A_{k-1}+T(a_k,b_k))\bmod 2^{32},\qquad
  rd=A_{n-1}.
\end{equation}
其中 $T$ 按源表达式选择 $T_s$ 或 $T_b$。first 建立局部累加状态，add 只更新该状态，last 在加入末项
后才产生一次 GPR 写回；因此一个 $n$ 项点积只需一次通用寄存器结果写回。$n<2$ 时仍使用普通标量序列。

\begin{algorithm}[H]
\caption{\texttt{xmacacc} 的分阶段乘累加语义}\label{alg:xmacacc}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\Procedure{XMacAcc}{$phase,mode,a,b$}
  \If{$mode=\mathrm{signed}$}
    \State $term\gets T_s(a,b)$
  \Else
    \State $term\gets T_b(a,b)$
  \EndIf
  \If{$phase=\mathrm{first}$}
    \State $A\gets term$
  \Else
    \State $A\gets (A+term)\bmod 2^{32}$
  \EndIf
  \If{$phase=\mathrm{last}$}
    \State \Return $A$ \Comment{写回 \code{rd}}
  \Else
    \State \Return \textsc{NoGPRWrite}
  \EndIf
\EndProcedure
\end{algorithmic}
\end{algorithm}

指令数与仿真拟合证据。

\subsubsection{\texttt{xlistfind}：链表节点查找}

设链表节点包含后继指针和 info 指针。\code{xlistfind.idx} 以 \code{rs1} 为表头、\code{rs2[15:0]}
为目标索引，比较每个 info 数据字的高 16 位；\code{xlistfind.data} 则比较低 8 位。两者命中时返回
当前节点地址，遍历到空后继仍未命中时返回 0。每个节点的逻辑为
\begin{equation}
  next=\mathrm{Mem}_{32}[node],\quad info=\mathrm{Mem}_{32}[node+4],\quad
  value=\mathrm{Mem}_{32}[info].
\end{equation}
状态机利用 D-cache 内两组私有异步副本并行查询 $node$ 与 $node+4$，随后查询 $info$；任何一步 miss
均复用统一数据总线并在响应后继续。副本输出只进入查找器局部寄存器，普通 load 仍使用同步 BRAM。
该指令只读内存，不改变链表链接或 info 数据。

\begin{algorithm}[H]
\caption{\texttt{xlistfind} 的链表节点查找算法}\label{alg:xlistfind}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\Procedure{XListFind}{$head,target,dataMode$}
  \State $node\gets head$; $target\gets target[15:0]$
  \While{$node\neq0$}
    \State $next\gets\operatorname{Load}_{32}(node)$
    \State $info\gets\operatorname{Load}_{32}(node+4)$
    \State $word\gets\operatorname{Load}_{32}(info)$
    \If{$dataMode$}
      \State $candidate\gets\mathrm{zext}_{16}(word[7:0])$
    \Else
      \State $candidate\gets word[31:16]$
    \EndIf
    \If{$candidate=target$}
      \State \Return $node$
    \EndIf
    \State $node\gets next$
  \EndWhile
  \State \Return $0$
\EndProcedure
\end{algorithmic}
\end{algorithm}

\subsubsection{\texttt{xlistrev}：链表链接反转}

每个节点首字为后继指针。设当前节点地址为 $cur$、已反转前缀的表头为 $prev$，单步语义为
\begin{equation}
  next\leftarrow \mathrm{Mem}_{32}[cur],\qquad
  \mathrm{Mem}_{32}[cur]\leftarrow prev,\qquad (prev,cur)\leftarrow(cur,next).
\end{equation}
\code{xlistrev.init} 以 \code{rs1} 为 $cur$、\code{rs2} 为 $prev$ 处理一个节点，并把处理后的
$(next,cur)$ 建立为内部链状态；\code{xlistrev.loop} 不再读取通用寄存器中的链指针，而是使用该内部
$(cur,prev)$ 再处理一个节点。当 $next\neq0$ 时，硬件把 PC 重定向回同一条 \code{xlistrev.loop}；
当 $next=0$ 时不再重定向，并返回当前节点地址作为反转后的新表头。两条指令各自的语义如下。
\begin{algorithm}[H]
\caption{\texttt{xlistrev.init} 与 \texttt{xlistrev.loop} 的逐指令语义}\label{alg:xlistrev}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\Procedure{XListRev.Init}{$rs1,rs2$}
  \State $cur\gets rs1$
  \State $prev\gets rs2$
  \If{$cur=0$}
    \State $state.cur\gets0$
    \State $state.prev\gets0$
    \State \Return $0$
  \EndIf
  \State $next\gets\operatorname{Load}_{32}(cur)$
  \State $\operatorname{Store}_{32}(cur,prev)$
  \State $state.cur\gets next$
  \State $state.prev\gets cur$
  \State \Return $next$
\EndProcedure
\Statex
\Procedure{XListRev.Loop}{$loopPC$}
  \State $cur\gets state.cur$
  \State $prev\gets state.prev$
  \If{$cur=0$}
    \State \Return $prev$
  \EndIf
  \State $next\gets\operatorname{Load}_{32}(cur)$
  \State $\operatorname{Store}_{32}(cur,prev)$
  \State $state.cur\gets next$
  \State $state.prev\gets cur$
  \If{$next\neq0$}
    \State $PC\gets loopPC$
    \State \Return $next$
  \Else
    \State \Return $cur$
  \EndIf
\EndProcedure
\end{algorithmic}
\end{algorithm}

\subsubsection{\texttt{xmsum}：带裁剪的矩阵序列归约}

\code{rs1} 给出连续 32 位元素数组 $C$ 的首地址；$n=\mathrm{rs2}[31:16]$，
$clip=\mathrm{sext}_{32}(\mathrm{rs2}[15:0])$，处理元素数 $N=n^2$。$clip$ 是有符号累计和的裁剪
阈值：本项累计和以有符号数比较，超过阈值时本项贡献 10，下一项以自身元素值重新起始累计；未超过阈值
时，若当前元素按有符号数大于前一元素，则本项贡献 1。
\begin{algorithm}[H]
\caption{带有符号裁剪阈值的矩阵序列归约}\label{alg:xmsum}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\State $base\gets rs1$
\State $n\gets rs2[31:16]$
\State $clip\gets\mathrm{sext}_{32}(rs2[15:0])$
\State $S\gets0$
\State $P\gets0$
\State $R\gets0$
\State $restart\gets\mathbf{false}$
\State $i\gets0$
\While{$i<n^2$}
  \State $C\gets\operatorname{Load}_{32}(base+4i)$
  \If{$restart$}
    \State $S\gets C$
  \Else
    \State $S\gets S+C$
  \EndIf
  \If{$\operatorname{signed}(S)>clip$}
    \State $R\gets R+10$
    \State $restart\gets\mathbf{true}$
  \Else
    \State $restart\gets\mathbf{false}$
    \If{$\operatorname{signed}(C)>\operatorname{signed}(P)$}
      \State $R\gets R+1$
    \EndIf
  \EndIf
  \State $P\gets C$
  \State $i\gets i+1$
\EndWhile
\State \Return $\mathrm{sext}_{32}(R[15:0])$
\end{algorithmic}
\end{algorithm}

\subsubsection{\texttt{xdfacnt/xdfa4/xdfa4h}：有界字符状态推进}

该指令族实现八状态字符自动机。状态编码为起始、非法、符号后、指数标记后、整数、小数、指数符号后、
科学计数；转移函数记为 $q'=\delta(q,ch)$。零字节、逗号或非法转移使本次有界步停止。公开的步进
指令一次读取 \code{rs2} 所在的 32 位对齐字，并从该地址对应字节起至多处理四个字符；其公共语义
如算法~\ref{alg:xdfa4-step} 所示。对齐字末尾限制使 $available=4-(\mathrm{rs2}\bmod4)$，因此不会
访问下一个对齐字。逗号本身计入 $consumed$，零字节不计入；导致非法转移的非零字符计入
$consumed$，且返回状态为 \code{INVALID}。

\begin{algorithm}[H]
\caption{DFA 四字节有界步进的公共语义}\label{alg:xdfa4-step}
\small\linespread{0.90}\selectfont
\begin{algorithmic}
\setlength{\itemsep}{0pt}
\State $q\gets rs1[2:0]$
\State $mask\gets0$
\State $consumed\gets0$
\State $stopped\gets\mathbf{false}$
\State $available\gets4-(rs2\bmod4)$
\State $word\gets\operatorname{Load}_{32}(rs2\mathbin{\&}\mathtt{\sim3})$
\For{$i\gets0$ \textbf{to} $available-1$}
  \If{$\neg stopped$}
    \State $ch\gets word[8(rs2\bmod4+i)+:8]$
    \If{$ch=0$}
      \State $stopped\gets\mathbf{true}$
    \ElsIf{$ch=\mathtt{','}$}
      \State $consumed\gets consumed+1$
      \State $stopped\gets\mathbf{true}$
    \Else
      \State $q'\gets\delta(q,ch)$
      \State $mask\gets mask\mathbin{|}\operatorname{transitionMask}(q,ch)$
      \State $consumed\gets consumed+1$
      \State $q\gets q'$
      \If{$q'=\mathrm{INVALID}$}
        \State $stopped\gets\mathbf{true}$
      \EndIf
    \EndIf
  \EndIf
\EndFor
\State \Return $\operatorname{Pack}(mask,stopped,consumed,q)$
\end{algorithmic}
\end{algorithm}

打包结果的实际字段为 $\mathrm{rd}[14:7]=mask$、$\mathrm{rd}[6]=stopped$、
$\mathrm{rd}[5:3]=consumed$、$\mathrm{rd}[2:0]=q$，高 17 位清零。各条公开指令的输入、状态副作用
和返回值分别为：

\begin{itemize}
  \item \code{xdfacnt.init}：不使用 \code{rs1/rs2} 的值；清零 8 项转移计数器、8 项终态计数器和
    跨字待提交掩码；\code{rd} 返回 0。
  \item \code{xdfacnt.read}：以 \code{rs1[2:0]} 选择一项转移计数器，\code{rs2} 不参与运算；
    不修改任何 DFA 状态，\code{rd} 返回所选转移计数。
  \item \code{xdfacnt.commit}：以 \code{rs1[7:0]} 为状态掩码，\code{rs2} 不参与运算；每个置位
    对应的转移计数器递增一次，不修改终态计数器和待提交掩码；\code{rd} 返回 0。
  \item \code{xdfa4}：以 \code{rs1[2:0]} 为起始状态、\code{rs2} 为首字符地址，执行算法
    \ref{alg:xdfa4-step}；除读取包含该地址的对齐字外，不修改计数器或待提交掩码，\code{rd} 返回
    上述当前步的打包结果。
  \item \code{xdfa4h.step}：输入同 \code{xdfa4}，且 \code{rd} 同样返回当前步的打包结果。若本步
    未停止，则把当前 $mask$ 并入内部待提交掩码而不修改计数器；若本步停止，则将待提交掩码与当前
    $mask$ 合并，对合并掩码中每个置位状态的转移计数器各递增一次，同时将返回状态 $q$ 对应的终态
    计数器递增一次，随后清零待提交掩码。
  \item \code{xdfa4h.read}：以 \code{rs1[2:0]} 选择一项终态计数器，\code{rs2} 不参与运算；
    不修改任何 DFA 状态，\code{rd} 返回所选终态计数。
  \item \code{xdfa4p}：忽略 \code{rs1}，以内部状态或起始状态处理 \code{rs2} 指向的当前对齐字，
    \code{rd} 直接返回已消费字符后的下一指针；同时保存内部 DFA 状态和停止标志。跨字未停止时累积
    状态掩码，停止时提交转移与终态计数；终端空 token 的 NUL 步不额外增加最终状态计数。
\end{itemize}

全部计数器和跨字待提交掩码均为 EXU 内部架构状态；普通 \code{xdfa4} 不直接修改它们。

\subsubsection{编译器自动指令选择}

硬件指令只有被编译器从普通程序语义中稳定识别，才能形成可复用的体系结构能力。为此，我们在 GCC 的
RISC-V 目标支持中补充受目标选项控制的指令选择：测试程序仍使用原有 C 源文件，没有嵌入面向
自定义指令的手写汇编片段，也没有把原函数替换为手工编写的专用实现。关闭相应目标选项时，编译器继续
生成标准 RV32 指令序列；开启后，只有满足语义、数据类型和操作数约束的结构才会被选择为自定义指令。

实现路径遵循 GCC 公开的目标后端扩展机制。局部算术表达式先进入 RTL，由机器描述中的
\code{define\_peephole2} 识别等价序列，再由 \code{define\_insn} 约束操作数并输出目标编码；跨基本块的
循环、链式更新和归约结构则在语言无关的 GIMPLE 表示上识别，经具有明确语义的 internal function
下沉至 RTL，最后汇入同一机器描述完成选择。GCC 官方将机器描述定义为目标指令模式的载体，并允许
其中包含目标相关的指令与 peephole 模式\footnote{GCC Internals：
\href{https://gcc.gnu.org/onlinedocs/gccint/Machine-Desc.html}{Machine Descriptions}、
\href{https://gcc.gnu.org/onlinedocs/gccint/Patterns.html}{Insn Patterns}、
\href{https://gcc.gnu.org/onlinedocs/gccint/Peephole-Definitions.html}{Peephole Definitions}。}；GIMPLE、内部函数和优化 pass
则是 GCC 中端表达并逐级降低较大语义结构的公开接口\footnote{GCC Internals：
\href{https://gcc.gnu.org/onlinedocs/gccint/Tree-SSA.html}{Tree SSA}、
\href{https://gcc.gnu.org/onlinedocs/gccint/Internal-Functions.html}{Internal Functions}、
\href{https://gcc.gnu.org/onlinedocs/gccint/Pass-manager.html}{Pass Manager}。}。

每类能力均由独立 target option 显式启用，组织方式与 GCC 上游 RISC-V 厂商扩展一致。GCC 的
\code{.opt} 文件支持使用 \code{Target}、\code{Mask} 或 \code{Var} 声明目标选项
\footnote{GCC Internals：
\href{https://gcc.gnu.org/onlinedocs/gccint/Option-file-format.html}{Option file format}。}；上游 RISC-V 后端也以独立机器

\subsection{一致性、阻塞与异常边界}

无内部访存的 \code{xcrcu8/xbmul} 进入加速结果通路；\code{xmbm/xmacacc} 进入复用窄 DSP 的长算术
通路；其余单元在 EXU 保持当前指令，直至状态机完成并与后级握手。\code{xlistfind} 的 load、
\code{xlistrev} 的 load/store、\code{xmsum} 的 load 及 DFA 的对齐字读取均复用统一数据总线。控制流
冲刷不会提交年轻指令的请求；已经握手的链表写入则按普通 store 的可见顺序完成。每条指令只驱动其
唯一 ResultKind lane，使阻塞控制、访存副作用和普通整数结果选择保持清晰边界。
