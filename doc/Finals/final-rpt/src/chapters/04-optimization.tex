\section{性能与时序优化}\label{sec:optimization}

\subsection{优化方法}

优化过程把程序运行时间和实现时序作为一组联合指标：首先从完整工作负载的周期、停顿、分支与访存
统计中定位高频事件，再对 Vivado 最差路径的逻辑级数、布线占比和扇出进行结构归因，最后以回归测试、
实现报告和真实板测共同评价。\textbf{性能数据只在相同正式负载、相同迭代规模和正确 CRC 之间比较}；WNS
记录与产生对应 bitstream 的实现一一配对。

这些观测也说明“减少动态指令”并不自动等于减少周期：早期链表原型虽然覆盖了高频节点循环，却把原本

副作用和实际周期，而不是只采用理想化的每节点指令节省量。

\subsection{前端控制流优化}

控制流优化围绕“查询深度、容量冲突、后端修正开销”同步展开。BTB 扩展为 512 项后，采用 8 个 64 项
bank 分摊异步查询深度；valid、tag、目标地址与 2-bit 方向状态共同决定预测。更新端使用窄 shadow
保存更新所需信息，避免后端写入信息经宽比较网络回绕到当前取指拍。条件分支按局部饱和计数器判断，
JAL 和 return 直接采用目标，return 可由两项 RAS 消除 BTB 目标别名。

后端一旦发现预测方向或目标不一致，即生成一次重定向事件。所谓\textbf{重定向邮箱}，是指一组保存
待处理目标地址和有效位的寄存器：当 IFU 当拍受存储响应或下游反压影响而不能立即接收新 PC 时，EXU
产生的目标不会丢失，而是写入邮箱；IFU 接收后清除有效位。重定向后的第一条取指采用顺序下一 PC，
随后恢复正常预测，从而切断“后端比较---重定向---异步 BTB 查询---下一 PC”在同一拍内形成的组合链。
预测、校验、更新与冲刷的完整流程见第\ref{sec:frontend}节。

\subsection{缓存、同步 load 与专用查询优化}

数据缓存由 2\,KiB 扩展为 4\,KiB 双 bank，以容量和 bank 选择共同降低直接映射冲突。主数据使用
同步 BRAM，普通命中 load 在 LSU 周期取得数据并形成顺序前递。此前的通用 late-load 异步副本已从
最终结构已移除，避免 tag/data、扩展选择和多个消费者重新构成长组合路径。load 相关消费者统一遵守
EXU/LSU/WBU 的生产者有效协议；数据尚未从同步 BRAM 对齐时保持停顿。

\subsection{执行和后端通路优化}

普通整数 ALU、直接结果、长算术、硬件加速和 load 结果划分为五类。相邻快速结果采用分组编码选择，
其控制信号不进入地址、M/B、自定义指令和 CSR 等长路径。地址操作数单独注册，D-cache 查询只携带
所需 index/tag；加速单元的请求、响应和结果分别设置边界寄存。该结构让每类消费者只观察必需的数据
与有效标志，减小宽选择器、扇出和跨模块组合回路。

结果分区阶段还采用 routed 报告作定量验收：未分区起点的 WNS/TNS/失败端点数为
$-1.242$~ns/$-3223.578$~ns/9022，分区候选变为 $-0.767$~ns/$-653.245$~ns/3472，绝对 TNS
减少 79.7\%，失败端点减少 61.5\%\evidence{E-PROF-BACKEND}。对应 16M 指令定向运行由
24,071,573 cycles 增至 24,143,856 cycles，仅增加 0.3003\%。因此该方案的保留依据是显著压缩后端
违例路径总体规模，同时把流水停顿代价限制在预设阈值内，而不是宣称它本身提高 CoreMark 运行速度。

最终结构进一步把 IFU 输出改为两个固定槽，避免动态队列读 Mux 进入所有译码路径；ID/EX 使用独立
payload/valid 寄存器，重定向直接清除 valid。紧邻快速整数结果的分支插入一拍，并在 LSU 边界解析
注册后的比较结果；即 EXU 完成比较后先把错误标志写入 EXU/LSU 寄存器，下一拍再触发重定向，从而
把分支比较从 ID/EX valid 输入锥移开。CSR 文件也局部化到 EXU，以两阶段
事务切断 IDU 到 CSR 旧值及 \code{mepc/mtvec} 的宽路径。

\subsection{乘法与位操作优化}

普通低位乘法使用较短 DSP 流水；操作数满足定宽条件时进入窄乘法通路，高位乘法仍使用完整
有符号或无符号乘积。部分 RISC-V B 扩展按逻辑深度分为短组合操作和迭代操作，避免简单的移位加法
或符号扩展承担通用迭代延迟。多周期指令在结果未就绪期间持续提供目的寄存器占用信息，使 IDU 对
相关消费者保持停顿；结果有效后才允许旁路或提交。

矩阵整数路径新增 \code{xmbm/xmacacc}：前者融合 16-bit 乘法和乘积位域运算，后者让 first/add/last
序列在乘法器局部累加。最终 \code{xmacacc} 结果直接从累加器寄存器退休，消除复制到通用结果寄存器的
额外跳转。当前迭代 B 单元则裁剪到工作负载实际保留的 \code{clz/ctz}，使未用的迭代操作硬件可被综合删除。

正式 10,000 次程序镜像和经校核的一周期乘法 IP 重新生成 bitstream；四项 CRC 均正确，板测时间为
\textbf{6.74501768\,s}，对应 routed WNS 为 $-0.590$\,ns，post-route physical optimization WNS 为 $-0.580$\,ns。
P19 保持 P18 的 RTL、DCP 与测试源码不变，仅由 GCC 自动识别计算结构并选择目标指令；三次板测均为
\textbf{6.69115404\,s}。此后的上板点将融合位域乘法、指针式 DFA、链表查询和乘累加逐步纳入硬件，
P21 的三次正确 capture 均为 5.346451040\,s\evidence{E-BOARD-COMB}。P22--P29 记录保留提交链上的结构重整：其中 P22 删除
八组普通 load 异步数据副本，只付出约 8.786\,ms 拟合代价；P25 用相关停顿换取地址组合链缩短；P29
在相同 RTL 上完成 GCC 后端迁移后，最终拟合时间为 \textbf{5.292462350\,s}，但尚未上板。

\subsection{工程可复现性}

实现脚本统一完成 SystemVerilog 生成与打包、Vivado 工程源刷新、IP/OOC 生成、布局布线、报告提取和
归档。流程显式记录程序镜像身份、请求与实际频率、实现命令、关键报告和板测原始输出；顶层实现并发
不低于 16，IP/OOC 并发不低于 4。对内联仿真模型，仿真保留模型，综合与打包阶段排除模型并绑定
同名 Vivado IP，确保仿真接口、流水时延与物理实现配置一致。
