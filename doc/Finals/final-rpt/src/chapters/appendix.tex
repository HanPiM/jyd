\subsection{GCC 自定义指令匹配摘要}\label{app:gcc-custom-match}

本节概括普通 C 源码到自定义指令的自动选择路径。局部算术结构在 GIMPLE 或 RTL
数据依赖上匹配；包含循环、访存或跨基本块状态的结构先由 GIMPLE pass 验证，再转换为 internal
function（IFN），经 optab 或目标展开器下沉到机器描述（MD）。各路径受独立 target option 控制，
选项关闭时保留标准 RV32 指令。正式构建不加载探索性插件，也不以包装函数强制替换源码。

\begin{table}[H]\centering\scriptsize
\caption{当前已实现的 GCC 自动匹配路径}\label{tab:gcc-custom-implemented}
\setlength{\tabcolsep}{3pt}
\begin{tabular}{@{}p{0.15\linewidth}p{0.15\linewidth}p{0.42\linewidth}p{0.20\linewidth}@{}}
\toprule
\textbf{指令}&\textbf{匹配层}&\textbf{主要约束}&\textbf{下沉路径}\\\midrule
\code{xcrcu8}&GIMPLE CRC 与 MD&
八次反向 CRC 更新、8-bit 数据、16-bit 状态及固定多项式&
\TopStack{\code{CRC\_REV} IFN/optab\\$\rightarrow$ \code{bitmanip.md}}\\
\code{xbmul}&RTL peephole2&

\TopStack{\code{packed\_field\_mul}\\\code{define\_insn}}\\
\code{xmbm}&GIMPLE pass&

\TopStack{\code{IFN\_XMACACC\_*}\\\code{\_MATRIX}\\$\rightarrow$ target expand/MD}\\

\end{tabular}
\end{table}

\code{xbmul} 的关键点不是源码文本匹配，而是 RTL 数据依赖和临时量活跃性。删减后的 MD 结构示意为：
{\small
\begin{verbatim}
(define_peephole2
  [shift-by-2; shift-by-5; and-15; and-127; multiply]
  "TARGET_XBMUL && eliminated_temporaries_are_dead"
  [(set rd (unspec:SI [src] UNSPEC_XBMUL))])
\end{verbatim}
}
只要移位量、掩码、源操作数或中间值用途不同，模式就不成立。跨基本块指令则先证明整个语义结构；
其 GIMPLE pass 的核心流程可概括为：
{\small
\begin{verbatim}
if (clipped_rising_score_p(n, base, clip))
  replace_with_internal_call(
      IFN_CLIPPED_RISING_SCORE_REDUCE, n, base, clip);
\end{verbatim}
}
其中判定函数同时检查循环边界、加载地址、递推关系和返回值。链表反转采用同类方法验证重链接循环。
关闭对应 \code{-m} 选项或任一结构条件不满足时，均保留原软件控制流。

\code{xmbm} 的 GIMPLE 匹配先沿两个字段表达式回溯到共同乘积，再以二输入 IFN 替换末端乘法。关键
逻辑可简化为：
{\small
\begin{verbatim}
if (field_p(lhs, 2, 15, &p2)
    && field_p(rhs, 5, 127, &p5) && p2 == p5)
  replace_with_ifn(IFN_XMBM, product_arg0, product_arg1);
\end{verbatim}
}

\code{xmacacc} 不只把单条乘法换成目标指令。GIMPLE pass 先把经过校验的矩阵循环变为带 $n,C,A,B$
四个参数的 IFN；RISC-V 目标展开器随后构造三层地址循环，并对每个点积生成：
{\small
\begin{verbatim}
emit xmacacc.first  (A[0],   B[0]);
emit xmacacc.add    (A[k],   B[k]);   // 0 < k < n-1
result = xmacacc.last(A[n-1], B[n-1]);
store result to C;
\end{verbatim}
}
位域矩阵入口选择 bfirst/badd/blast；$n=0$ 不写结果，$n=1$ 使用标量乘法与字段提取。这样点积的局部
累加状态留在执行单元，只有 last 产生一次 GPR 结果。\code{xlistfind} 则把已验证的查找函数降为
\code{IFN\_XLISTFIND(list,info)}，MD 展开先检查目标索引符号，再选择 idx 或 data 编码。

编译器实现通过六组正、反例检查。正式 ELF 静态审计同时要求各已启用指令族出现、六个
\code{xmacacc} 阶段和两个 \code{xlistfind} 子操作齐全，并确认不存在强制包装调用；审计结果为
38/1/5/2/4/6 个 \code{xcrcu8/xlistrev/xmsum/xdfa4p/xlistfind/xmacacc} 位置。组合矩阵热点由
\code{xmacacc} 整体展开，因此 \code{xmbm} 在该 ELF 中被覆盖；单独开启 \code{-mxmbm} 的正例仍能
生成对应两处指令。

\subsection{AI 工具使用声明}

项目研发和技术文档整理过程中使用 OpenAI 的 ChatGPT/Codex 系列工具提供辅助。分赛区阶段主要使用
ChatGPT（GPT-4o），总决赛阶段主要使用 Codex（GPT-5 系列，Codex CLI 0.147.0）；版本号按实际使用
阶段记录，云端模型的小版本由服务端滚动更新。团队对体系结构决策、代码合入、测试结果和最终文字负责，
AI 工具不替代人工设计评审、功能验证、FPGA 实现或板级测评。

按各类工作的投入量粗略估算，AI 辅助约占：体系结构分析与优化决策 15\%，RTL/GCC/脚本代码编写与
修改 30\%，验证方案与日志整理 30\%，技术文档文字、LaTeX 排版和 TikZ 图表 60\%；折合项目总体工作量
约 25\%。这些比例表示工具参与草拟、检索或整理的工作量，不表示内容未经人工复核。主要用途如下：

  \item \textbf{使用边界：}性能与 WNS 数据均来自仿真、Vivado 报告或板测原始记录；指令语义、接口时序和
  硬件结构均经过团队审核，不使用 AI 生成的虚构数据或未经验证的结论。
\end{itemize}
