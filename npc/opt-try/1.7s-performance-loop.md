# NPC 1.75 s / 1.70 s 性能优化记录

本轮从 `withMext-v2` 在 280 MHz 下 1.868 s 的已验证版本继续优化。验收目标是不超过 1.75 s，期望约 1.70 s；保持顺序单发射，最终频率不低于 250 MHz，优先保持 280 MHz 或更高。

时序判定规则：最终版本必须 WNS >= 0；若 `-0.1 ns < WNS < 0`，允许试探性生成比特流并上板评估收益，但不能作为最终验收结果。允许调用 Vivado 创建所需 IP；若自动创建失败则暂停并请求人工协助。每轮尝试记录性能、功能、时序、产物和保留/回退结论。

## 基线

- RTL/上板：523,155,579 cycles，CPI 1.3755，280 MHz 换算 1.86841 s，上板约 1.868 s。
- 动态指令：380,344,412。
- 最终 IDU stall：100,928,980 cycles；EXU 90,373,057，LSU 10,555,686。
- DCache：110,606,979 次 cacheable load，98,377,478 hit，12,229,501 miss。
- M 扩展：`mul` 发射 10,496,004 次，IDU 占用 31,104,004 cycles。

## EXP-005：ADD/ADDI-only 晚数据旁路

- 日期：2026-07-17
- 状态：性能通过，时序继续优化
- 改动：IDU 只为 `ADD/ADDI` load-use 放行；EXU 原 ALU 始终使用原寄存器操作数，另设单个 32 位加法器计算晚数据结果，避免 DCache 数据进入 M/branch/CSR/store 和通用 ALU ready 网络。
- RTL perf：460,406,199 cycles，380,344,384 instructions，CPI 1.2105；280 MHz 换算 1.64431 s，相对 1.86841 s 基线减少 12.00%。
- 性能结论：相对完整晚旁路仅增加 383,017 cycles（0.083%），矩阵热点收益几乎全部来自 load→ADD/ADDI。
- 280 MHz Retiming：WNS -0.247 ns、TNS -12.170 ns、125 failing endpoints、WHS +0.069 ns。最差路径为 `reg1AddImm`/DCache 控制经流水级组合反压至 PC/IFU PC clock-enable，约 78% 为布线延迟；晚加法器本身已不是前五条最差路径。
- 结论：性能超过目标，但违例仍大于 0.1 ns，不生成比特流；下一步切断 EXU→IDU→IFU 的组合 ready 反压。
- 原始计数：`npc/history_perf/7c35f2e4/0717T01_06_29.405629732/`。

## EXP-006：通用 Chisel Queue 弹性缓冲

- 日期：2026-07-17
- 状态：回退
- 假设：IDU→EXU 使用深度 2、可 flush 队列，以 registered full 状态切断 EXU ready 到 IFU PC 的组合路径。
- 功能：格式、Verilog、`add`、`switch` 与 difftest 通过；截至 288M 指令的主样例周期轨迹与 EXP-005 完全一致。
- 打包修复：通用 Queue 额外生成 `Queue2_DecodedInst.sv` 和 `ram_2x353.sv`，Vivado 工程需显式纳入；两文件加入后综合通过。
- 时序：280 MHz Retiming WNS -1.265 ns。最差路径从 Queue `deq_ptr` 经异步 distributed RAM/控制到 PC CE；353-bit payload 的通用 Queue 被综合为大规模 RAMD32/RAMD64E 和指针选择网络。
- 结论：虽然切断了原组合 ready，通用宽 Queue 的异步存储实现制造更差路径，回退。下一步改用显式双寄存器 skid buffer，输出直接来自寄存器且无 RAM/指针选择。

## EXP-012：BTB IP 化与 4096 data / 2048 paired-tag

- 日期：2026-07-17
- 状态：BTB 改动保留；paired-tag 性能通过但时序失败，改为 banked tag
- BTB 改动：16-entry、恰好 32-bit 的 BTB entry 从 `Reg(Vec)` 改为现有 `dist_mem_gen_32x32` 异步读 IP，保持零周期预测；用可复位 valid mask 屏蔽未初始化内容。`add`、`switch` 通过。
- paired-tag 结构：data 4096×32；tag 2048×6，地址 `addr[13:3]`，共享 tag `addr[17:14]`，`addr[2]` 选择两个独立 valid。为同时服务 query 和 refill/store 的异步 read-modify-write 使用两份 tag 副本。
- paired-tag RTL perf：457,368,689 cycles，CPI 1.202512，262.5 MHz 换算 1.742357 s；完整样例、`add`、`load-store`、`switch` 通过。相对普通 4096 tag 仅增加 57,210 cycles。
- PLL/IP 门禁：请求/实际均为 262.50000 MHz，VCO 1050 MHz；data=4096×32、tag=2048×6、mypll 的 output products 和 OOC DCP 均重建。
- Vivado 时序：`Performance_Retiming` routed WNS -1.458 ns、TNS -1308.368 ns、WHS +0.072 ns，1608 个 failing endpoints；不生成 bitstream。最差路径为地址→update tag 副本异步读→组合 tag/valid RMW→query/update tag RAM 同拍写端，route 占 83%。
- 原始计数：`npc/history_perf/7c35f2e4/0717T03_16_59.976241335/`。
- 结论：共享 tag 本身需要 RMW，制造了比原查询路径更差的同步写关键路径，回退 paired 语义。下一版保持逐字 tag 语义，把 4096 项按 `addr[2]` 拆为两个 2048×5 bank；每次只写一个 bank，无 RMW，性能应与普通 4096 完全等价。

## EXP-014：同步 tag BRAM + IDU 预查询止损

- 日期：2026-07-17
- 状态：功能/性能通过、时序失败；停止局部修补并准备切换方向
- 结构：tag 改为 4096×5 simple-dual-port BRAM，IDU 指令 `fire` 时以预计算 `reg1AddImm` 发起一拍同步读，结果与指令进入 EXU 对齐；data BRAM 仍由 EXU 地址驱动。store 地址从预查询地址中拆出；tag 同 index 读写显式 forward；held EXU 遇 tag 写时首版通过刷新读处理。
- IP：`blk_mem_gen_dcache_tag`，read latency=1、default init=0，OOC 资源 1×RAMB36E1，DCP SHA-256 `360040192bca3aa2972c12f80f876778432042168569035a6c6341b43f3ad2ac`。PLL requested/actual 均为 262.50000 MHz。
- 功能/性能：reformat/checkformat/Verilog/pack-fpga 通过；lint 仅 6 个允许忽略的 `PINCONNECTEMPTY`；`add`、`load-store`、`switch` 和完整 `withMext-v2` 通过，对齐 assert 无触发。完整结果与异步 4096 逐项一致：457,311,479 cycles，262.5 MHz 换算 1.742139 s。原始计数：`npc/history_perf/4f294a14/0717T03_58_01.821120718/`。
- 首轮时序：当前工程策略（place `ExtraPostPlacementOpt`）routed WNS -0.597 ns、TNS -51.606 ns、WHS +0.052 ns。异步 tag 查询路径已消失；新最差路径为 tag BRAM Q→hit/ready→IDU `fire`→held-refresh 地址 mux/碰撞比较→`collisionReg` 或下一拍 tag BRAM ADDRB。
- 路径分类：① tag BRAM Q→hit/ready→IDU `fire`→collision register，WNS -0.597 ns；② tag BRAM Q→hit/ready→下一拍 tag BRAM ADDRB，约 -0.540/-0.521/-0.485 ns；③ IFU/IDU instruction→GPR async read→地址加法→tag BRAM ADDRB，-0.504 ns；④ tag BRAM Q→hit→6 级 ready/allowIn→pipeline CE，约 -0.490~-0.464 ns。③、④与 held-refresh 无关。
- 频率/策略判断：262.5 MHz 周期 3.810 ns；降到最低允许的 250 MHz 只增加约 0.190 ns，仍无法关闭约 0.5~0.6 ns 的多组独立违例，而且当前 457,311,479 cycles 在 250 MHz 为 1.829246 s，性能也不合格。此前同类策略扫描只带来约 0.01~0.1 ns 差异，不足以覆盖该缺口。
- 最后草稿：已把 BRAM 地址固定直连 IDU，并以 held override entry 代替 refresh 重读；reformat/checkformat/Verilog、`add`、`load-store` 通过。该草稿预计只消除①、②，无法消除③、④，故不再消耗一次完整 Vivado run。
- 结论：同步 BRAM 成功保持性能并将异步 tag 的 1390 failing endpoints 降至 208，但继续闭合时序必须引入额外流水/重放或切断 hit→ready，而不再是 tag 存储的局部优化。按方向止损规则封存，切换到小容量 DCache + 乘法器降延迟方向。
- 封存：commit `490100c`，专用分支 `opt-archive-sync-tag-4096`。`opt-loop` 已开始恢复到 commit `4f294a1` 的异步 tag RTL/工程基线；尚未配置新容量 IP，也未开始下一方向的代码、仿真或 Vivado 实验。
- 下一方向收益依据：当前 `mul_gen_0` 为 4 级流水，主样例 `mul` issued 10,496,004 次；降为 3 级理论上可回收约 10.5M cycles，而 512-word DCache 在 262.5 MHz 达到 1.75 s 只需减少约 1.03M cycles。先以 512/1024-word async tag 恢复较容易收敛的时序，再验证 3-stage multiplier IP 和四项 M 架构测试。
- 审核门禁：按用户要求，选定该候选方向后暂停；在用户审核批准前，不配置 512/1024-word IP、不修改 multiplier latency/IP、不运行候选仿真或 implementation。
