# NPC 1.75 s / 1.70 s 性能优化记录

本轮从 `withMext-v2` 在 280 MHz 下 1.868 s 的已验证版本继续优化。验收目标是不超过 1.75 s，期望约 1.70 s；保持顺序单发射，最终频率不低于 250 MHz，优先保持 280 MHz 或更高。

时序判定规则：最终版本必须 WNS >= 0；若 `-0.1 ns < WNS < 0`，允许试探性生成比特流并上板评估收益，但不能作为最终验收结果。允许调用 Vivado 创建所需 IP；若自动创建失败则暂停并请求人工协助。每轮尝试记录性能、功能、时序、产物和保留/回退结论。

## 本轮执行约束

- 本文是 1.75 s / 1.70 s 目标的独立尝试记录，并持续保存在 `opt-loop`；每次实现、策略或频点尝试无论成功失败都追加事实、产物和结论，不接到旧的 1.9 s 记录后面。
- 实现、修复、代码审阅、Vivado/IP、专项测试和数据分析等边界清晰的任务建议交给 subagent；主代理按文件划分任务、统一审查共享工作树并执行集成门禁，subagent 默认不提交。
- 允许用 Vivado Tcl 创建或修改所需 IP。若无法自动创建或接口/延迟无法确认一致，保存命令与日志并暂停，请用户协助，不使用不匹配的临时 IP 得出结论。
- 最终候选必须 WNS >= 0；无约束硬错误、hold 通过且 `-0.1 ns < WNS < 0` 时，可试探性生成 bitstream 测量收益，但该 bitstream 不能用于最终验收。
- 同一方向经过多轮结构调整、有限策略和合理降频仍无法同时满足时序与性能时，将该方向代码、Vivado 状态和产物封存到新分支，再回到 `opt-loop` 的已知干净基线换方向；本文继续留在 `opt-loop` 维护。
- 只要 PLL/Clock Wizard 的 requested 与 actual 频率不一致，就把时钟问题作为上板高风险硬门禁；必须改到精确可实现的 requested 值、重建全部相关 IP/OOC DCP，并记录 VCO 和分频后才可继续。
- 每次提出假设、分派任务、处理时序和决定保留/回退时持续对照 `npc/opt-iter-flow.md`；若偏离流程，先在对应实验中记录原因和替代门禁。

## EXP-005：ADD/ADDI-only 晚数据旁路

- 日期：2026-07-17
- 状态：性能通过，时序继续优化
- 改动：IDU 只为 `ADD/ADDI` load-use 放行；EXU 原 ALU 始终使用原寄存器操作数，另设单个 32 位加法器计算晚数据结果，避免 DCache 数据进入 M/branch/CSR/store 和通用 ALU ready 网络。
- RTL perf：460,406,199 cycles，380,344,384 instructions，CPI 1.2105；280 MHz 换算 1.64431 s，相对 1.86841 s 基线减少 12.00%。
- 性能结论：相对完整晚旁路仅增加 383,017 cycles（0.083%），矩阵热点收益几乎全部来自 load→ADD/ADDI。
- 280 MHz Retiming：WNS -0.247 ns、TNS -12.170 ns、125 failing endpoints、WHS +0.069 ns。最差路径为 `reg1AddImm`/DCache 控制经流水级组合反压至 PC/IFU PC clock-enable，约 78% 为布线延迟；晚加法器本身已不是前五条最差路径。
- 结论：性能超过目标，但违例仍大于 0.1 ns，不生成比特流；下一步切断 EXU→IDU→IFU 的组合 ready 反压。
- 原始计数：`npc/history_perf/7c35f2e4/0717T01_06_29.405629732/`。

## EXP-006：通用 Chisel Queue 弹性缓冲

- 日期：2026-07-17
- 状态：回退
- 假设：IDU→EXU 使用深度 2、可 flush 队列，以 registered full 状态切断 EXU ready 到 IFU PC 的组合路径。
- 功能：格式、Verilog、`add`、`switch` 与 difftest 通过；截至 288M 指令的主样例周期轨迹与 EXP-005 完全一致。

- 时序：280 MHz Retiming WNS -1.265 ns。最差路径从 Queue `deq_ptr` 经异步 distributed RAM/控制到 PC CE；353-bit payload 的通用 Queue 被综合为大规模 RAMD32/RAMD64E 和指针选择网络。
- 结论：虽然切断了原组合 ready，通用宽 Queue 的异步存储实现制造更差路径，回退。下一步改用显式双寄存器 skid buffer，输出直接来自寄存器且无 RAM/指针选择。

## EXP-012：BTB IP 化与 4096 data / 2048 paired-tag

- 日期：2026-07-17
- 状态：BTB 改动保留；paired-tag 性能通过但时序失败，改为 banked tag
- BTB 改动：16-entry、恰好 32-bit 的 BTB entry 从 `Reg(Vec)` 改为现有 `dist_mem_gen_32x32` 异步读 IP，保持零周期预测；用可复位 valid mask 屏蔽未初始化内容。`add`、`switch` 通过。
- paired-tag 结构：data 4096×32；tag 2048×6，地址 `addr[13:3]`，共享 tag `addr[17:14]`，`addr[2]` 选择两个独立 valid。为同时服务 query 和 refill/store 的异步 read-modify-write 使用两份 tag 副本。
- paired-tag RTL perf：457,368,689 cycles，CPI 1.202512，262.5 MHz 换算 1.742357 s；完整样例、`add`、`load-store`、`switch` 通过。相对普通 4096 tag 仅增加 57,210 cycles。
- PLL/IP 门禁：请求/实际均为 262.50000 MHz，VCO 1050 MHz；data=4096×32、tag=2048×6、mypll 的 output products 和 OOC DCP 均重建。
- Vivado 时序：`Performance_Retiming` routed WNS -1.458 ns、TNS -1308.368 ns、WHS +0.072 ns，1608 个 failing endpoints；不生成 bitstream。最差路径为地址→update tag 副本异步读→组合 tag/valid RMW→query/update tag RAM 同拍写端，route 占 83%。
- 原始计数：`npc/history_perf/7c35f2e4/0717T03_16_59.976241335/`。
- 结论：共享 tag 本身需要 RMW，制造了比原查询路径更差的同步写关键路径，回退 paired 语义。下一版保持逐字 tag 语义，把 4096 项按 `addr[2]` 拆为两个 2048×5 bank；每次只写一个 bank，无 RMW，性能应与普通 4096 完全等价。
