# 1.9 秒性能优化尝试记录

## 目标和记录规则

- 保持顺序单发射；最终频率不得低于 250 MHz，优先维持 280 MHz 或更高。
- 固定 COE 测试在三次有效上板结果中的中位数应不超过 1900 ms，且结果必须正确。
- 每个尝试都记录，包括无收益、功能失败、时序失败和回退的尝试。原始日志放在不提交的输出目录，本文件记录摘要及相对路径/哈希。
- 380,000,000 条动态指令样例的 CPI 为 `elapsed_ms * frequency_MHz * 1000 / 380000000`。
- 轻微负 WNS 的结果仅用于诊断；最终候选必须 `WNS >= 0`。

辅助解析命令示例：

```sh
python3 npc/scripts/summarize_fpga_perf.py \
  --candidate baseline --frequency-mhz 280 \
  --timing-report "$JYD_VIVADO_PROJ_HOME/digital_twin.runs/impl_1/top_timing_summary_routed.rpt" \
  --board-log run-1.log --board-log run-2.log --board-log run-3.log \
  --jsonl results.jsonl --markdown
```

### EXP-007：整字 store write-allocate（最终保留）

- 根因：主样例矩阵热点频繁执行栈上计数器的 `lw/add/sw`；原设计每次 store 都使 DCache 项失效，制造大量 load-use miss。
- 第一版 store-hit 写通可将主样例降至 523,156,157 周期，但 tag hit 串入写控制导致放置后约 WNS -0.657 ns。
- 最终结构：
  - cacheable 整字 `sw` 无条件 write-allocate，同时写入完整 32 位数据和有效 tag，不依赖 tag hit；
  - byte/half store 保守 invalidate；
  - 年轻 store 优先于较老 WBU load fill，并递增 store epoch，防止迟到 fill 覆盖新数据；
  - DRAM 写路径不变。
- 主样例 RTL perf：523,156,157 周期，CPI 1.3755；相对 544,246,238 周期减少 21,090,081（3.875%），280 MHz 预计 1868 ms。
- 280 MHz 时序：
  - `impl_1`：WNS -0.059 ns，TNS -0.202 ns（5 端点）；
  - `impl_Auto_1`：WNS +0.019 ns，TNS 0，WHS +0.087 ns，全部约束满足。
- 上板：第一次烧录因 JTAG target 被锁定而失败，属于基础设施失败；随后三次有效结果均为 `37801868`（1868 ms），37+8 项正确。
- 完整回归：`add/load-store/switch/if-else/recursion` 全 PASS；`mul/mulh/mulhu/mulhsu` 定向 M 测试全 PASS；格式、Verilog 生成通过。Verilog lint 仅 7 条已知 `PINCONNECTEMPTY` warning，并因 warning-as-error 返回非零。
- 结论：保留并提交。达到本轮至少 1900 ms 的目标，同时保持顺序单发射与 280 MHz。
